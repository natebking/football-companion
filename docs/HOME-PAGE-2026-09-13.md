# Home page and game selection — September 13, 2026

When no game is selected, the app now explains its purpose and presents the game selector directly. The inactive Watch next, Last play, score, TV-sync and journal controls are hidden. Choosing a game replaces the introduction with the existing analysis view. Replays bypass the home view; a valid saved unfinished game still resumes, and a missing or finished saved game never substitutes an unrelated live game.

## Design decisions

- Lead with “Know what to watch next,” followed by concrete benefits: player involvement, drive context and the consequences of the last play. The introduction does not promise video, formation recognition or a forecast.
- Make choosing a game the primary action. The existing league, search, schedule and finished-game controls appear inline. Games focuses this search on the home page and opens the same selector as a dialog during a game.
- Keep one selector, one state and one set of game buttons. Moving its container between the home view and dialog preserves searches and avoids restarting team logo loads on routine renders.
- Distinguish an initial load, an empty day, a search with no matches, an unavailable schedule and a failed refresh. Empty days offer a direct Browse finished games action. Failed refreshes retain listings with a stale-data message; retries are available. Background polling does not replace a known empty day with a loading message.
- Keep the introduction shorter on mobile. The game list scrolls within the desktop card; on mobile it uses the page's normal scrolling. The existing light/dark palette applies throughout.
- Selection moves keyboard focus to Watch next. Closing the game dialog restores its trigger; home Games and Skip to games focus the inline search.

These choices apply [Nielsen Norman Group's empty-state guidance](https://www.nngroup.com/articles/empty-state-interface-design/): explain the state, introduce the relevant task and provide an action where it is needed. The restrained introduction and clear entry action also follow [GOV.UK's start-page pattern](https://design-system.service.gov.uk/patterns/start-using-a-service/). These are design principles, not evidence that this particular layout has improved conversion or learning; no user study was performed.

- `/tests/logo-rendering.html`: all 13 existing logo/search/scoreboard checks passed. Empty-state assertions now point to the inline replay action.

- Visual checks: desktop light and mobile dark; no horizontal overflow at widths 390 or 320 pixels. No uncaught runtime errors in the isolated browser flow.
- Static build and whitespace checks pass. No analysis model, play classification, historical percentages or TV-delay release rules changed.
